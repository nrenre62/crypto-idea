## Scale probe detail (phase 2)

For each of 50 users, seeded the tier + counter with rules disabled (users can't set their own `tier`),
then made **real boundary writes**: at-limit create ALLOWED, over-limit create DENIED, and a
counter forge-down (lower the counter with no child delete) DENIED. All three resource types covered
per tier. Limits verified against `firestore.rules`:

| tier (public name) | portfolios | coins/portfolio | tx/coin |
|---|---|---|---|
| free (**Starter**) | 1 | 10 | 50 |
| pro | 3 | 50 | 2,000 |
| premium | 15 | 1,000 | 5,000 |

The **hard ceiling** (`hardMax`, coins ≤ 1,000) and the **counter-no-forge** rule (a client may only keep
or +1 a gating counter; it comes down only via the trusted `reconcileMyCounters` callable) both held —
the denial-of-wallet / paywall-bypass class stays closed.

## Isolation probe detail (phase 3)

Attacker context (alice) against a seeded victim (bob) + the server-only collections. Every one DENIED:
`get`, `list`, `write`, `update`, `delete` on bob's `users/{uid}`, `portfolios`, `coins`, `transactions`,
and `learn/progress`; client reads/writes of `config`, `audit`, `rateLimits`, `webhookEvents`, and
`cache/**` (shared market data is proxy-only); and self-escalation — alice writing `tier`, `admin`,
`role`, `isAdmin`, `deleted`, `premiumLimits` into her **own** profile. This re-proves ISOLATION.md's
audit against today's rules rather than assuming it.

## Per-tab data-flow & privacy map (phase 4)

| tab | writes (path · fields) | personal data · where | leaves the app? |
|---|---|---|---|
| **Portfolio** | `users/{uid}/portfolios/…/coins/…/transactions` (type, amount, priceAtBuy, date); portfolio create/rename/delete; coin add/remove; `journal` edits | Financial holdings + user text (thesis, portfolio names) · under `users/{uid}` | Only coin **ids** transit `/api/prices?ids=` (first-party proxy); no amounts/identity |
| **Research** | `users/{uid}/portfolios/{pid}.coinOrder` **only** (R32 drag-reorder, ≤1000, display-only) | Holdings-derived figures (in-memory, not persisted); `coinOrder` | `/api/history` + `/api/prices` carry coin ids only. **AI is offline** (`askClaude` throws) — no thesis/holdings/chat text leaves the client |
| **Journal** | `users/{uid}/…/coins/{id}.journal` (thesis, changeMyMind, funnel, status; each ≤2000) | User-authored thesis text · on the coin doc; owner-only ("only you can see your journal") | No `/api` calls; nothing external |
| **Learn** | `users/{uid}/learn/progress` (xp, streak, lastActivity, completedLessons, updatedAt) | Gamification aggregates only; **quiz answers/selections never persisted** (React state only) | No. Lesson content is a static bundle, no PII |
| **Search** | via Add-coin: `users/{uid}/…/coins/{id}` (+ optional Buy-Journal `journal`) | Search query (interest); Buy-Journal text | `/api/search?q=` sends **only the query** (no uid); server does **not** log the query with any identifier; `/api/trending` sends nothing |

**Cross-cutting sweep:** no client `fetch`/XHR/beacon to any host other than the first-party `/api/*`
proxy, Firebase SDK endpoints, and the documented admin-config-gated GA4/Plausible/Termly loaders. The
service worker's cache guard is GET **and** same-origin **and** not `/api/**`, so no per-user API
response is ever cached — nothing user-scoped can leak across accounts on a shared device.

## OBSERVATIONS (not confirmed bugs — context / watch-items)

1. **Denial honesty is a KNOWN, tracked item.** A plan-limit denial returns `permission-denied`,
   indistinguishable at the wire from other causes — the mislabeled-limit-toast class. Already
   diagnosed and addressed: `ERRORS.md` §A1, `NEXT-STEPS.md` §DI (DI-1 honest errors). Not re-filed.
2. **Latent AI seam carries thesis text into Research's in-memory holdings** (`utils/coins.js` copies
   `coin.journal` onto each research holding for "AI journal-context later"). Today it is NOT placed in
   `portfolioContext`, NOT read by the conviction mock, and never leaves the client (AI offline). A
   **watch-item for when the B2 AI proxy ships** — that is the moment thesis text could travel, and it
   must only ever go through the server-side proxy + output validator.
3. **Journal copy asserts a thesis→AI flow that isn't wired yet** (`Journal.jsx` "helps the AI give you
   better Research & Ask answers"). Forward-looking (the thesis→Research carry is real and tested by the
   MOAT walkthrough; only the AI consumption is pending), so not strictly false — but worth revisiting
   when the AI ships or if the claim should be softened until then.
4. **`window.CI_PORTFOLIO` / `CI_HOLDINGS` fallback** in `useHoldings.js` is a non-Firestore holdings
   source for the standalone build; never hit in-app (the prop is always supplied). Noted as a
   data-layer bypass path to keep an eye on.
5. **Journal writes send the whole `journal` map** (read-modify-write off an in-memory copy) rather than
   a field-scoped merge; a stale in-memory copy could clobber a concurrently-changed sub-field. Minor,
   within the R24 baseline.

## What was NOT covered (gaps — not passes)

- **Rules + integration solo tiers were not run as separate suites this pass.** The isolation/scale
  probes exercise the rules directly (and more adversarially than the standing `test:rules` suite), but
  the `test:integration:solo` callable-body tier (real signup, callable side-effects) was **not** run —
  the account-lifecycle signup-shape assertion is therefore **INCONCLUSIVE**, not green. Run
  `npm run test:integration:solo` to close it.
- **No live app/browser probe** — this hunt is data-layer + static-audit only. UI-level issues (a
  mislabeled toast actually rendering, a race in an overlay) aren't in scope here.
- **AI proxy path** is unbuilt (offline by design), so its output-safety / data-egress behavior could
  not be exercised — only the current fail-closed seam was confirmed.
- **Search-query server logging** was audited statically (no uid-linked logging found); not verified
  against a running functions emulator this pass.
