# Crypto Idea — project guide for Claude

Crypto portfolio tracker + DCA calculator PWA. **Vite + React 18 + Firebase.**

## How to run (always start the whole stack together)
- **`npm run start:all`** — emulators + dev server in one lifecycle (start one → start all; Ctrl-C stops all).
  - Vite dev: http://localhost:3000  · Hosting (built `dist/`): http://localhost:5000  · Emulator UI: http://localhost:4000
  - Emulators: auth 9099, firestore 8080, functions 5001 (`/api`), pubsub 8085.
- `npm run dev` alone runs ONLY Vite → `/api/*` fails with `ECONNREFUSED :5001`. Don't use it alone.
- **`start:all` brings up an EMPTY in-memory emulator — it does NOT seed.** After it's up, seed once
  with `node functions/scripts/seed-emulator.js` (owners `admin@test.com`/`admin2@test.com`, `manager@test.com`, role-less `legacy@test.com` + `free@`/`pro@test.com`, all `test1234`). Re-seed after every restart (the emulator is in-memory). See "Seed test data" below.
- Realtime Database & Storage emulators are intentionally off — the app doesn't use them.

## Build, test, deploy
- `npm run build` — Vite build + stamps the service worker + the **no-names `dist/` guard** (`scripts/check-dist-names.js`, #24): the build FAILS if a real investor name (Buffett/Munger/Marks/Graham) leaks into the shipped bundle. Must be clean before deploy.
- `npm run test:unit` (Vitest, ~552) · `npm run test:rules` (36) · `npm run test:integration` (19) — component/hook + Firestore rules + data layer + **live callables** (rules/integration via emulators; counts drift — run them for live numbers). ⚠️ **Don't run `test:unit` while `start:all` is up** — the 59-file parallel jsdom run starves for CPU against the emulators and a handful of `waitFor`s hit the 5000ms default timeout, so a red run on a loaded machine is *inconclusive, not a failure* (measured both ways 2026-07-22; see `NEXT-STEPS.md` §FLAKE). (Unit also covers the server-side `functions/validate-output.js` + `guards.js` + `billing.js` + `universe-utils.js`, imported directly.)
  - **`:solo` variants** (`test:rules:solo`, `test:integration:solo`) run against an isolated emulator on alternate ports via `firebase.solo.json`, so tests work while a full `start:all` stack holds the default ports.
  - **`test:integration` now starts the FUNCTIONS emulator too** and `tests/functions-callable.test.js` invokes real callables over HTTP. This is the only tier that executes a callable *body* — the client-side tests all mock `httpsCallable`, which is how the ERRORS.md **C6** un-suspend bug shipped. Add a case here when a callable's behaviour (not just its pure helpers) matters. It discovers the functions port from the emulator hub, so it follows whichever config started the run.
- `npm run deploy` — build + `firebase deploy` (needs the Blaze plan for functions).

## Architecture
- **Multi-page Vite:** `index.html` = static marketing landing (`#dca` = free DCA calculator); `app.html` = React user app (`main.jsx` routes `/app`, `/edge`, `/pro-success`); `admin.html` = SEPARATE admin app (`admin-main.jsx`) served at `/admin` — its code is NOT in the user bundle.
- **Code-split for fast first loads:** `main.jsx` lazy-loads routes; `vite.config.js` `manualChunks` isolates Firebase into its own cached chunk. Keep the entry chunk small.
- **Backend = `functions/index.js`** (Node 22, CommonJS). `api` HTTP function proxies CoinGecko with shared, cached Firestore docs so upstream cost is FLAT regardless of user count. PayPal + admin callables also live here.
- **Data layer:** Firestore via `firebase-database.js` / `firebase-auth.js`; counters maintained with `writeBatch` + `increment`. **Multi-device live sync (C-A3, 2026-07-03):** `watchPortfolios` (metas), `watchCoins` (the ACTIVE portfolio only; a coin-doc change — incl. the `txCount` bump every tx write makes — re-reads just that coin's transactions) and `watchLearnProgress` keep a second device's edits live without reloads; all other data stays fetch-once.
- **Research tab** is a self-contained feature module in `src/features/research/` (its own `components/hooks/utils/api/styles`), reached from the bottom nav. See the "Research tab" section below.
- **App design system + 5 tabs:** the user app uses the editorial/paper design (Fraunces + Hanken, deep-green accent) defined in **`src/styles/app.css`**, scoped under a **`.ci-app`** wrapper placed only on the nav + new screens so it can't collide with the Research tab's `.research-root` (both reuse generic class names like `.card`). Bottom nav has **5 tabs**: Portfolio · Research · **Journal** · **Learn** · Search. **The Journal/thesis feature is WIRED** (`src/components/Journal.jsx` + the Search Buy-Journal prompt): a thesis persists on the coin doc as `journal {thesis, changeMyMind, status, priceAtAdd, createdAt, funnel?{dilution,volume,yield}}` (validated by `firestore.rules`/`validJournal`+`validFunnel`, no new collection — bounded by the coin cap). The optional `funnel` holds the three **manual-research findings** (#27 — dilution/unlocks · real volume vs wash-trading · real yield), captured on the Search Buy-Journal prompt and editable in the Journal detail overlay (single source of truth: `src/data/journal-funnel.js`; pure `cleanFunnel` in `utils/journal.js`). Save persists it via `addCoin`'s optional 2nd arg; the Journal tab lists the active portfolio's coins that have a thesis and its detail overlay records the "is your thesis still intact?" decision (intact/review/challenged) via `reviewThesis` → `updateCoinJournal`. **The Learn tab is WIRED** (`Learn.jsx` + `useLearn` + pure `utils/learn.js`): real level/XP/streak/module-state from persisted progress (`users/{uid}/learn/progress`, `validLearnProgress`), **quiz-gated** lesson completion; the full library is **9 modules / 50 lessons** (no-names voice, hand-authored quizzes), one file per module under `src/data/learn/` composed by the `src/data/learn-content.js` index (validated by `tests/unit/learn-content.test.js`: valid `correctIdx` + no author names). **Conviction-signal pills are LIVE off the rubric reducer but MOCK-fed:** the 4-state pills (🟢/🟡/🔴/⬛) on Research coin cards are graded by the pure `src/features/research/utils/conviction.js` reducer (≥2-source gate, reason chips, catalyst expiry — #8/#9/#11), driven by deterministic mock evidence (`data/mock-conviction.js`); the **live AI evidence is Wave B** (swap the mock seam for the per-coin cache). **Every** user screen is now on the `.ci-app` paper design — including Account/Detail/AddEntry/CoinInfo/Login (migrated design-only; logic/handlers untouched). `app.css` carries reusable class sets per area: coin drill-in (`detail-head`/`price-hero`/`kv-row`/`pnl-row`/`tx-row`), forms (`field-input`/`seg`/`submit-buy`), auth+billing (`auth-wrap`/`plan-card`/`cycle-card`), and Account (`usage-row`/`bar`/`tier-badge`/`priv-btn`). The landing (`index.html`) is the v18 "why before you buy" design. E2E coverage: `tests/unit/CryptoIdea.walkthrough.test.jsx`.

## Security model (don't break these)
- **Only `dist/` ships to the browser.** `functions/`, `firestore.rules`, configs, scripts, tests are backend/build-only. No secret ever ships — API keys live in `functions/` + the locked `config/app` Firestore doc. The in-bundle `VITE_FIREBASE_*` web config is public by design.
- **Admin = Firebase custom claims, never an email list**, in TWO roles: **owner** `{admin:true, role:"owner"}` (set only by `functions/scripts/set-admin.js`) and **manager** `{admin:true, role:"manager"}` (granted by an owner from the panel). `role` is `""` for plain users and legacy role-less admins.
- Firestore rules are the security boundary; users can't change their own `tier`; `/config` is server-only. The blanket `users` update/delete allowances are **owner-only** (`isAdminOwner()`); reads stay open to any admin. Verify rule changes with `npm run test:rules`.
- Output encoding: React auto-escapes; the static landing uses `textContent`, never `innerHTML`, for API data. **CSP `script-src` has NO `unsafe-inline`** (D12, 2026-07-03): all page scripts are external files in `public/` (`landing.js`, `sw-register.js`, `termly-embed.js`) — never add an inline `<script>` to any HTML entry; the build ships zero inline scripts.

## Admin & privacy (functions/index.js)
- **Admin is a SEPARATE app at `/admin`** (`admin.html` / `src/admin-main.jsx`), not part of the user app. It has its own login that verifies the `{admin:true}` claim and signs out non-admins. The user bundle contains no admin code. A different URL is NOT the security boundary — the claim check (server-side in every admin function, re-checked in the admin app) is. **2FA for admins is deferred to go-live** (needs Blaze + Identity Platform MFA).
- **Owners can't be wiped out (protection by IDENTITY):** an owner can never be deleted, trashed, demoted or self-deleted, and a **manager may not act on an owner at all** (suspend / sign-out / tier / limits / trash / delete all refuse). `MIN_ADMINS=2` + `countAdmins()`/`countActiveOwners()` remain only as a secondary floor; `getStats` returns `activeOwners`. Keep ≥2 owners.
- Admin callables, gated per role in `functions/index.js` via `assertAdmin`/`assertManager`/`assertOwner`/`assertFreshOwner` (pure helpers `roleOf`/`isOwner`/`requireAdmin`/`requireManager`/`requireOwner`/`requireFreshAuth` live in `functions/guards.js`):
  - **any admin** (`assertAdmin`): `getStats` (combined usage, no personal data), `listUsers` (full list — Auth+profile merge, operational data only, capped 5000, returns `role`), `lookupUser` (returns `role`), `listAudit`.
  - **manager or owner** (`assertManager`): `setUserTier`, `setPremiumLimits`, `suspendUser`, `restoreUser`, **`adminTrashUser`** (soft-delete to the 30-day trash) and **`adminSignOutUser`** (revoke a target's refresh tokens) — BL-2, 2026-07-03.
  - **owner only** (`assertOwner`): `deleteUser` (GDPR erasure; blocks self-target).
  - **owner + step-up re-auth** (`assertFreshOwner` — password re-auth within ~600s, toggled by the server flag `config/app.flags.stepUpReauth`, default ON): `getAdminConfig` (reads saved config; secrets returned as set-flags only), `saveConfig`, **`setManagerRole({email, grant})`**.
  `setAdminClaim` is **REMOVED** — the old export always throws `permission-denied`; `src/api/admin.js` exports `setManagerRole`. Granting/revoking a manager lives in an **owner-only "Admin access" tab** (`src/api/admin-auth.js` `getAdminRole()`/`reauthAdmin()`), NOT the Users tab. The panel also has an **Empty-trash bulk purge** and a reserved **AI Settings card** (Anthropic key via the `keep()` set-flag idiom; conviction-cache controls disabled until B5).
- Users tab = full list, searched + paginated 50/page client-side; row click opens per-user actions. (Earlier this was on-demand-lookup-only; now it's a full list.)
- Settings (**owner only, behind step-up re-auth**): `saveConfig` writes the locked `config/app` doc; the form pre-fills from `getAdminConfig` and a blank secret field keeps the saved value (never wiped on re-save).
- **App Controls (public flags):** `config/app.flags` = `{maintenance, signupsEnabled}`, set via the Settings "App Controls" toggles. The app reads them from the PUBLIC **`/api/config`** endpoint (non-secret only, CDN-cached ~60s) on load → maintenance shows a "we'll be right back" screen; signups-off disables the Register tab. Flags apply within ~60s (cache). Note: signups-off is a client gate; hard server enforcement needs an Auth `beforeCreate` blocking function at go-live.
- **Analytics & legal:** `config/app.analytics{ga4,plausible}` + `config/app.legal{termlyUuid,termlyPrivacyId,termlyTermsId,cookieBanner}`, exposed via `/api/config`. `public/site-meta.js` (on landing+app) injects GA4/Plausible/Termly-consent when set; `privacy.html`/`terms.html` auto-embed Termly docs by id.
